# BT-RJ-001 offline verification, 2026-10-23

## Scope

Implemented a standalone, opt-in Beat Twin Bitwig adapter consuming structural `midi-delivery-v1` Remote Jam messages. There is **no network service**, Bitwig mutation in this development environment, or real audio proof. The upstream producer is still Remote Jam PR #23 (draft).

## Evidence obtained

In an isolated local test fixture containing the proposed consumer implementation and fake Bitwig MIDI port, the following succeeded:

- TypeScript 5.8.3 `tsc -p .` with strict ES2022/NodeNext settings: **passed**.
- Node.js 22.16.0 `node --experimental-strip-types --test test/remote-jam.test.ts`: **13 passed, 0 failed**.
- Tests cover structural MIDI contract and range validation, operator/peer checks, note channel mapping, unsupported MIDI classes, stop cleanup, duplicate/sequence-gap behavior, foreign peer refusal, revocation, uncertain host errors, concurrent events/arming, malformed frame cleanup and authenticated RPC mapping.

**Limits of that evidence:** the isolated test fixture is a candidate implementation; the actual GitHub PR files were published through the GitHub API and **the checked-out PR head was not retested here**. A complete Beat Twin checkout and its pinned toolchain are not available in this runtime. The repository requires **Node >=26** and TypeScript ^5.9. The whole Beat Twin suite, architecture check, browser, and local controller have not been run against this PR.

1. On Node >=26 with the real repository: `pnpm install --frozen-lockfile`, `pnpm --filter @beat-twin/bitwig-adapter build`, `pnpm --filter @beat-twin/bitwig-adapter test`, `pnpm test`, and `pnpm check:architecture`.
